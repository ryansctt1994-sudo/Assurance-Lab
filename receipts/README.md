# Receipts

Machine-generated evidence bundles, one directory per receipt, each sealed:
`sha256sum -c output-hashes.sha256` inside the directory checks every file,
and `commitment.json` holds the SHA-256 of that hash file.

`dev/` holds receipts for the **development lineage** (PR #2) only. They are
not evidence about the published main baseline (`c175fbd`, 32 obligations),
whose only reproduction receipts are under `assurance-validation/reproduction/`.

| Receipt | What it covers |
|---|---|
| `dev/v2-acceptance-<commit>/` | matrix v2 (full denominators, cache independence, v1 against `b535b1a`), the replica snapshot-integrity repair (corruption classes with each control credited separately, retained `KeyError` counterexamples replayed against `b535b1a` and `c175fbd`), the replica model checker's state, snapshot and validation counts, the full test suite's raw output, and the snapshot-bound campaign report for the named commit. Generated by `scripts/v2_acceptance_receipt.py` from a clean checkout. |

A receipt records evidence for a decision; it does not make one. Promotion
is the owner's call.
